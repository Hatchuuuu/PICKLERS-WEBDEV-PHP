# Route & action compatibility map

The whole application is served by the Symfony kernel (`Picklers\Kernel`); see docs/symfony-migration/sections.md. `Picklers\Admin\Http\AdminArea` decides which requests are the admin console (admin firewall and error pages):

| Request | Area | Notes |
|---|---|---|
| `/admin`, `/admin.php`, **any** `/admin/*` path | Admin | Unknown `/admin/*` paths get the admin 404. |
| `/api`, `/api.php` with `action=admin_*` or `action=switch_user` (query, form or JSON body) | Admin | Same firewall, CSRF, capability checks, services and audit as `/admin/api`. |
| Everything else (`/`, `/auth`, `/app`, `/owner`, other `/api` actions…) | Player/owner | `web` firewall. |

There is no second copy of any admin rule.

## Action contract (`action=` parameter)

Mutations require **POST** and a CSRF token (`X-CSRF-Token` header or `csrf_token` field, token id `admin`); otherwise 405 / 403. Responses are JSON `{success, message, changed, …}`; refusals use 4xx with a human message (`field` names the offending input). Every action is denied (403) for non-administrators — asserted for all of them in `SecurityTest::testEveryDeclaredActionIsRoutedAndGuarded`.

## Session (one session, owned by Symfony)

- Symfony owns the session (`framework.session`, native PHP storage and handler): cookie `picklers_session` (name and lifetime read from `config/app.php`), path `/`, HttpOnly, SameSite=Lax, Secure on HTTPS, strict mode.
- Keys (Symfony's attribute bag): `picklers_user_id`, `picklers_last_activity`, `picklers_auth_at`, `picklers_impersonation`. Sessions opened before the session moved to Symfony sign in once more.
- Sign-in/out: `Web\Controller\AuthController` (Symfony password hasher on the existing hashes; session id rotated on sign-in; sign-out invalidates the whole session).
- The admin reads the session only through `Picklers\Admin\Security\PlatformSession` (Symfony `SessionInterface`; `migrate()` when the acting identity changes, `invalidate()` to sign out).
- Firewall `admin` is **stateless**: `AdminSessionAuthenticator` runs on every request, enforces the 2-hour idle timeout (shared constant), impersonation expiry/revocation, password-reset invalidation (`users.password_changed_at` vs `picklers_auth_at`), and loads the account fresh (`AdminUserProvider`) so role changes, deactivation and privilege revocation apply on the next request.
- Role mapping (`RoleMapper`): admin ⇔ `is_admin = 1` and not deactivated (the free-text `role` column never grants admin). `ROLE_PRIVILEGED_ADMIN` only from `admin_privileges`.
- CSRF: Symfony's built-in protection (`framework.csrf_protection`, session token storage). The banner on player/owner pages renders its `impersonation_stop` token with `csrf_token()`.
- Database: Doctrine DBAL opens its own MySQL connection (`config/symfony/packages/doctrine.php`, same `.env` variables, strict SQL mode). The shared booking/wallet/notification/provisioning rules live in `src/Domain/`; `Core\Database` runs on Doctrine's connection and its methods of the same name delegate to them, so each rule exists once.
- Impersonation: the session user becomes the target; the original admin is kept in `picklers_impersonation` (actor, target, reason, start, expiry ≤ 30 min). Every request (both firewalls) resolves it: expired → restore admin; admin no longer privileged → sign out. Session id rotates on start/stop. While impersonating, the console is closed except `admin_impersonation_stop`; sensitive player/owner actions are refused (`Web\Security\ImpersonationGate`); every mutating request is audited against the admin.
