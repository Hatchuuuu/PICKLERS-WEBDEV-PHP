## Prioritized findings and minimal fixes

1. **P1 — cancellation terms contradicted actual refunds (confirmed defect, corrected here).** `templates/web/partials/app/_modals.html.twig:733` promised 100% refunds at six hours; `BookingRepository.php:474–477,852–855` grants Pickle Credits refunds for pending bookings or at least 24 hours before play. A confirmed booking cancelled 12 hours before play loses credits despite the terms. Updated terms to distinguish pending, confirmed, started sessions and external payments. Changed `app.js:2253` eligibility description to avoid falsely claiming a pending same-day cancellation was made 24 hours in advance. It continues consuming the server's eligibility Boolean, without recomputing time in JavaScript. Accept: pending within 24 hours describes full refund; confirmed within 24 hours describes no refund; external payments direct to facility.

2. **P1 — unavailable funding presented as real payment (confirmed defect, disclosure corrected here).** `_tab-wallet.html.twig:7` advertised instant top-ups; `_modals.html.twig:377–467` offered Pay and GCash/Maya without an availability notice. `PlayerActions.php:267` deliberately rejects real top-ups outside explicitly enabled dev/test simulations. Opening Wallet → Top Up previously invited a payment flow guaranteed to fail in production. Added prominent unavailability and simulation-only disclosure, removed instant funding promise, changed initial and dynamic submission label to Request Top-Up. Preserved server fail-closed guard. `_modals.html.twig:715` also claimed secure gateway/tokenization processing; replaced with the current external payment arrangement. No conditional availability metadata exists in the player view, so the form remains available for explicit simulations and the server remains authoritative. Future smallest usability improvement: expose this existing server capability once in view data and conditionally replace production controls with an unavailable/support state; do not duplicate environment/flag interpretation in Twig.

3. **P1 — owner decline promised wallet refund for every method (confirmed defect, lead owns fix).** Discovery saw `_modals.html.twig` owner decline description at line128 and `owner.js:417` unconditionally reporting refund. `BookingRules::cancelAsStaff()` refunds only Pickle Credits and explicitly marks external payments for follow-up. Reproduce with a pending external-payment or Pay at Venue booking and decline: the old toast incorrectly claimed a wallet refund. Lead has since modified the response/toast while discovery ran. Verify latest owner response includes actual method/refund outcome; do not regress admin's already truthful outcome message.

4. **P2 for the selected local demo — misleading recovery promise (corrected).** The user selected local testing/presentation with no email/SMS or monitored support. `templates/web/auth.html.twig:644,721` previously sent recovery to a support mailbox. Forgot Password now uses a keyboard-accessible button to open the existing in-page recovery view, explicitly states that local-demo recovery is unavailable and no reset email/SMS will be sent, and points to provided presentation credentials. No reset service, token system or bypass was added. `auth-recovery-view.test.js` failed before the edit then passed, verifying truthful copy and both view-navigation directions.

5. **P2 — uncertain booking response encourages retry (source-confirmed wording; duplicate effect requires integration evidence).** `app.js:3533,3607` says network error, try again after a booking POST. A lost response may follow a committed booking. Smallest next investigation: simulate response loss after commit and check current booking reconciliation before proposing idempotency. Do not assume every network failure means nothing was booked.

## Existing strengths retained

- Player and owner modal wrappers call shared `UX.openDialog`/`closeDialog`; admin also delegates. `ux-core.js:81–231` adds runtime dialog role/name/modal semantics, traps Tab, closes Escape, restores focus and reference-counts scroll locks. Raw Twig missing roles are not findings.
- Player/owner toasts delegate to shared live announcements; admin has inline invalid-field feedback and loading `aria-busy` (`admin.js:135,293`). Admin cancellation already explicitly distinguishes wallet and external refunds (`templates/admin/_dialogs.html.twig:46–49`; `BookingAdminService.php:262–273`).
- Booking availability checks fail closed on failed/absent server responses and voucher application uses server quote. Existing frontend regression suites target these states; this review did not rerun those suites.
